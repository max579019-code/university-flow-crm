# University Flow CRM

MVP CRM-системы для управления взаимодействием ИТ Школы Ростелекома с высшими учебными заведениями.

## Проблема

Взаимодействие с вузами включает длительный процесс:

- поиск контактов;
- коммуникацию с представителями вуза;
- согласование ИТ-программ;
- обмен и подписание документов;
- передачу лицензий и материалов;
- обучение преподавателей;
- запуск занятий;
- контроль результатов.

При работе через таблицы, чаты и личные заметки сложно контролировать текущий статус каждого вуза, ответственных, сроки и возможные задержки.

## Решение

University Flow CRM объединяет работу с вузами в едином веб-интерфейсе и визуализирует путь взаимодействия через workflow из 14 этапов.

Система позволяет:

- вести единый реестр вузов;
- создавать карточки вузов;
- хранить ИТ-направления и ИТ-продукты;
- контролировать текущий этап взаимодействия;
- изменять этап и общий статус;
- добавлять комментарий к изменению;
- фильтровать вузы по статусу;
- формировать демонстрационный предпросмотр отчёта.

## Реализовано в MVP

- Главная страница CRM с реестром вузов.
- Фильтрация взаимодействий по статусу.
- Краткая статистика по демонстрационным данным.
- Добавление нового вуза.
- Валидация обязательных полей формы.
- Хранение данных в Firebase Firestore.
- Карточка вуза с детальной информацией.
- 14-этапный workflow взаимодействия с вузом.
- Изменение этапа workflow.
- Изменение общего статуса.
- Добавление и отображение комментария.
- Страница формирования демонстрационного отчёта.
- Публикация MVP в формате web-приложения.

## Технологии MVP

- FlutterFlow.
- Firebase Firestore.
- Web deployment FlutterFlow.

```text

```

## Структура данных

Основная коллекция Firestore:

```text
universities
```

Поля карточки вуза:

```text
name          — название вуза
city          — город
itDirection   — ИТ-направление
itProduct     — ИТ-продукт
currentStage  — номер этапа workflow
stageName     — название текущего этапа
status        — общий статус взаимодействия
comment       — последний комментарий
createdAt     — дата создания
updatedAt     — дата последнего обновления
```

## Ограничения MVP

MVP создан в условиях хакатона и использует только тестовые обезличенные данные.

В текущую версию не входят:

- интеграция с LMS и CMS сайта заказчика;
- авторизация через Keycloak;
- полноценная ролевая модель;
- загрузка файлов в статусы;
- реальная выгрузка отчётов в XLSX и PDF;
- PostgreSQL;
- Docker;
- Swagger/OpenAPI;
- полный аудит действий;
- промышленный защищённый контур.

## Целевая архитектура

```text
Пользователь
    ↓
Web-интерфейс
    ↓
Keycloak
    ↓
API Gateway
    ↓
Backend: Python / Node.js / Java
    ↓
PostgreSQL
    ↓
LMS + сайт заказчика + документооборот
```

Для промышленного внедрения предусматриваются:

- роли: пользователь, руководитель, администратор;
- API-интеграции;
- аудит действий;
- импорт и экспорт XLS/XLSX/PDF;
- Swagger/OpenAPI;
- Docker-контейнеризация;
- развёртывание в Linux-контуре;
- выполнение применимых требований информационной безопасности.
